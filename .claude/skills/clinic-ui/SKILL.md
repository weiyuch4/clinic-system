# Clinic UI rules

The living reference is the UI Component Guide artifact (https://claude.ai/artifact/Ah1X9XhJG4B6F3d6X6S9Bz). This skill is its working summary. **Before component work, read the guide; after it, update the guide** (Artifact tool: read the URL, edit, republish to the same URL) whenever a rule, component, or class changes.

Precedence: the user's words → this skill / the guide → existing code in this repo → `emil-design-eng` general taste. Use `emil-design-eng` for motion and polish details the guide doesn't cover. `prototype` only runs when the user asks for it.

## Two surfaces, two vocabularies

| | App pages (`_layout.css` + page `<style>`) | Admin back office (`admin.html`) |
|---|---|---|
| Who | Nurses, daily, often on phones | Clinic admin, mostly desktop |
| Primary button | `.bp` (pill, `#b5d7f5` fill, dark text) | `.btn-sm.primary` (6px radius, `--blue` fill) |
| Secondary button | `.act-btn` (pill outline) | `.btn-sm` |
| Inputs | `.si` (search), `.modal-input`, `.modal-select` | `.ln-field-input`, `.lfi`, `.ln-input`, `.sal-select` |
| Modes / tabs | page-local pill toggles (`.view-toggle`, `.inv-tabs`) | `.seg-toggle` + `.seg-btn`, `.ln-tab` |
| Month/week | `.month-nav` (nurse-ot) | `.month-picker` / `.week-picker` + `.mp-btn` |
| Control height | 36px | 32px |

Never mix the two vocabularies on one surface. Don't invent a new button class when one of these fits.

## Control height (the rule people notice first)

- Every button, input, select, segmented control and picker that can sit in a row uses the shared token: `height: var(--ctl-h)` (inputs, selects, square icon buttons) or `min-height: var(--ctl-h)` (text buttons). Vertical padding 0; center with flex.
- `--ctl-h` = 36px app pages, 32px admin, **44px on phones (≤767px) for both** — set in the mobile blocks. `--ctl-h-touch` = 44px always (touch-first controls such as the 點貨 stepper).
- Never build height out of padding + font size, and never hard-code `height:32px` inline — phones then can't grow it to 44.
- Grouped controls are measured by their outer frame: `.seg-toggle`, `.month-picker`, `.view-toggle`, `.inv-tabs` = `--ctl-h`; inner buttons fill it. `.seg-btn` must always be inside a `.seg-toggle`. `.mp-btn` = `calc(var(--ctl-h) - 6px)` square.
- Single-line inputs/selects inside `.ct` / `.modal-box` without their own height get `--ctl-h` automatically from a zero-specificity `:where()` rule in `_layout.css`.
- A text input with `flex:1` inside a **column** flex container collapses — use `flex:1 1 auto`.
- Exceptions (still equal to their neighbours): schedule-grid `.sched-time-btn` / `.sched-fill-btn` 28px; filter chips in their own row 32px (36px on phones).

## Tokens

- Colors, radii, shadows come from CSS variables (`--bg --card --border --text --sub --muted --g0 --g5 --g7 --r --shadow`; admin adds `--surface --text-1/2/3 --border-mid --blue --emerald --amber --red --radius-s --radius`). No new hard-coded hex in new code; page-specific colors become page tokens defined for light, `@media (prefers-color-scheme: dark) :root:not([data-theme=light])`, and `:root[data-theme=dark]`.
- Badge colors are semantic and fixed: blue 慢簽, green 代謝症候群, orange B肝, red 抽血, gray 自訂.
- Cards: `.card` (app) / `.card` + `.card-head` + body `padding:16px 24px 20px` (admin). At most **one primary button per card or modal**.

## Mobile shell (≤767px)

- Bottom nav is generated by `_layout.js` (`MOBILE_NAV`): 5 slots for everyone — 排班, 加班, 點貨, 備忘錄, 我的. Admin's 後台 lives in the 我的 menu. Nurse pages allowed on phones are listed in `MOBILE_ALLOWED` (no patient data on phones).
- Nav highlight `.mn-slide-pill` is the only thing that moves; `.mn-item` padding 3px, `.mn-ic` stretches. Navigate immediately on tap — no `setTimeout` before navigation. Keep `touch-action:manipulation`.
- `.tb` is `position:fixed` (iOS 26 colors the status bar from it). Never make it static, never fade body/`.tb`; page fade-in goes on `.ct` only.
- Sheets, backdrops and modals hang directly off `<body>` (never inside `.tb`). Closed full-screen overlays must be `visibility:hidden`/`display:none`, not just `opacity:0`.
- `.ct` bottom padding clears the nav (74px + safe area); toasts and floating action bars sit at `bottom: calc(74px + env(safe-area-inset-bottom) + 6–10px)`.
- Phone modals slide up from the bottom (`align-items:flex-end`, 20px top radius). Inputs are 16px font on phones (prevents iOS zoom).
- `.ct` is a scroll container and a flex column: page wrappers inside it need `flex-shrink:0`; sticky bars use `top: -<.ct padding>` (−18px desktop, −16px phone).

## Patterns already built — reuse them

- **Setup wizard** (`.wz*`, admin LINE 設定): one question per step, validate pasted values immediately, `.wz-check` for steps done on external sites, resume at the first unfinished step.
- **Count row + stepper** (`static/inventory.html`): grouped `.grp` cards, rows ≥64px, `.stp` −/number/＋ at 44px, per-item autosave after 600ms with error state, sticky `.cbar` progress + chips. An open count can be thrown away with the quiet `.danger-link.cancel-count` under 完成點貨 (confirm first; finished counts can't be cancelled, only reopened).
- **Patient list row** (`Layout.patientRow` / `patientTable`, `.p-table .pr-*`): shared by every follow-up list — style it in `_layout.css`, never per page. Color only marks what needs attention: one filled button per row (the main action; secondary actions such as 暫緩 are plain `.act-btn`, `act-warn` stays for the modal confirm); `.pr-more-btn` is borderless; overdue days are plain text under 15, amber 15–29, red 30+, never green; headers normal case 12px/500 with sort arrows only on hover or the sorted column; tab counts (`.tc-count`) and sidebar counts (`.nb`, hidden at 0) are plain numbers, not pills; `.b-line` is neutral gray. A page with one category passes `patientTable(rows, [], {hideCat:true})` so 類別 doesn't repeat on every row.
- **Tab hints** (`.tab-hint`, `.tab-hint-warn`/`-info`, in `_layout.css`): a quiet caption above the list — no box or fill; only the icon carries the tone. **Empty tabs** get `.empty` automatically from `_watchEmptyTabs()` when their `.tc-count` reads 0 or blank: muted label, count hidden, position unchanged. When adding a tab, add its key to the page's tab-switch list too (a missing key leaves the tab blank).
- **Zero steps back**: a count of 0 (dashboard tiles `.sc.is-zero`, 今日待處理 rows `.urg-item.is-zero`, empty tabs, sidebar `.nb.zero`) is muted so items with work stand out. A row that names a list links to it (`<a class="urg-item">` + chevron); to open a specific tab, set that page's `*_active_tab` sessionStorage key on click. The result count beside a list filter shows only while filtering (`.search-row.filtering`). Page-title help is `.ph-help` (28px), not inline styles.
- **Two searches, two jobs**: the top bar `.srch-input` finds any patient and opens `/patient` (it must never type into the page's list); the list filter `#search-input` (placeholder 「篩選名單：…」) sits in `.search-row`, 320px wide on desktop, full width on phones, with its count beside it.
- **Stock book / 帳冊紀錄** (`static/inventory.html`, `#m-ledger`, `.lg-*`): one item's record laid out like the paper book — 日期 / 摘要 / 收入 / 發出 / 結存, ROC year group rows, ≒ for estimates. App-made rows (點貨, 到貨) are read-only with a small `.lg-src` tag; typed rows are tapped to edit. Entry form accepts ROC dates (3/30, 115/3/30) and echoes how it read them; Enter walks the fields and saves on 結存, then the form clears for the next line.
- **Bottom sheet** (`.nurse-dd` + `.nurse-sheet-bd`).
- **Liquid-glass nav** values live in `--g-*` variables on `.mob-nav`; reduced-transparency falls back to opaque `--card`.

## Motion

Follow `emil-design-eng`, constrained by this product: nurses use it all day, so motion is crisp and rare.

- **Press feedback**: every pressable scales to `.97` on `:active`, instantly (no tween — pressed dozens of times a day). The shared list lives in the `:where(...)` "press feedback" block at the end of `_layout.css`; add new button classes there instead of writing per-class `:active` transforms.
- **Hover only on real pointers**: every `:hover` rule is wrapped in `@media(hover:hover){...}` (including inside dark-mode blocks). Write new hover rules the same way; otherwise a tap on a phone leaves the button stuck in its hover color. If a selector list mixes `:hover` with other states (`.x:hover,.x.focused`), keep the non-hover part outside the wrapper.
- **Reduced motion**: `@media(prefers-reduced-motion:reduce)` keeps fades but removes movement (nav pill glide, sheet travel, modal scale/slide, popover slide, press scaling). Blocks exist at the end of `_layout.css` and after the admin modal rules — extend them when adding a moving animation.
- Never `transition: all` — list the properties (`background-color`, `border-color`, `color`, `transform`, `opacity`). Never `ease-in` (closings use `ease-out`). UI transitions ≤250ms; only animate `transform`/`opacity` when something moves. Never animate from `scale(0)`. No animation on actions repeated dozens of times a day.

## Writing UI copy

Traditional Chinese, nurse's vocabulary (點貨, 安全量, 到貨), not system terms. Buttons say exactly what happens. Errors say what went wrong and how to fix it.

## Before you call UI work done

1. **Cache-bust**: when `_layout.css` / `_layout.js` change, bump `?v=` in **every** `static/*.html` that links them (all pages must use the same number).
2. **Changelog**: nurse-facing features get an entry at the top of `CHANGELOG` in `_layout.js` (bump `version`). Never mention `/admin/stats` or nurse activity tracking anywhere nurses can read (including 使用說明.html).
3. **Height audit** against a LOCAL server with test data (never production): `UI_AUDIT_PASS=... python tools/ui_height_audit.py desktop` and `... mobile` must report 0 mismatched pairs. Local setup: throwaway Postgres + `CLOUD_MODE=1`, seeded `synced_candidates` so list rows render; `.env.dev`'s Supabase DB is dead — the app runs on Railway now.
4. **Look once** at desktop 1366px and phone 390px, light and dark, for the screens you touched.
5. **Update the UI guide** artifact if any component, class, or rule changed.

## Prototypes

When the user invokes `prototype` in this repo, build the harness as standalone HTML under `static/prototypes/<slug>.html` (served at `/static/prototypes/<slug>.html`, linking `/static/_layout.css` so variants use real tokens). That folder is git-ignored; delete it after a variant is promoted.
